**Dependency audit — 16 September 2026**

Tunarr can get meaningful reliability and maintenance improvements without upgrading everything at once. Prioritize HTTP/XML fixes, HLS.js, and the TanStack Query/Router families; handle database, compiler, and UI migrations as separate changes. The largest barriers are custom native packaging, the Kysely patch, generated client compatibility, and older UI APIs.

This is a research and source-inspection audit of checkout `bed4ffb7`, not an upgrade or proof of compatibility. No dependencies were changed and no application tests were run. Existing test/config edits were preserved. Versions below are resolved versions, checked against `pnpm-lock.yaml`, with npm registry `latest` tags queried on the audit date. “Latest” is an inventory value, not an automatic recommendation. For 0.x packages, minor increments can break compatibility. All effort/risk judgments below are estimates from inspected integration points.

The companion [inventory](dependency-audit-2026-09-16-inventory.md) records all 136 distinct outdated direct dependency names returned by `pnpm outdated -r --format json`. Some packages have multiple workspace versions; the appendix preserves the command's representative current version. **Highest-value improvements**

HLS.js 1.7 adds parallel init-segment loading for faster startup, smoother audio-track switching, and fixes in live playback, subtitles, and low-latency HLS. These are directly relevant to `web/src/hooks/useHls.ts`, `components/Video.tsx`, and the troubleshooting player. Upstream reports no required runtime migration from 1.6, although tightened types can require edits. Validate startup, channel changes, reconnects, audio/subtitle selection, and long-running playback. [HLS.js 1.7 release notes](https://github.com/video-dev/hls.js/releases/tag/v1.7.0).

TanStack Query has accumulated a large amount of development since February 2024. Mutation scopes can serialize operations sharing an ID, potentially useful for repeated writes to one channel; adopting them would require application changes. Update the library and devtools first, then assess such features separately. The client generator in `web/openapi-ts.config.ts` emits Query hooks and Axios code, so check generated signatures and cache invalidation rather than treating Query as isolated. [Mutation scopes](https://tanstack.com/query/latest/docs/framework/react/guides/mutations#mutation-scopes).

React 19 introduces Actions, `useActionState`, `useOptimistic`, and ref-as-prop; React 19.2 adds `Activity` and `useEffectEvent`. Those enable new approaches to interactive forms and effect-driven UI, but existing React Hook Form and TanStack Form flows will not automatically benefit. The principal immediate benefit is moving onto the current ecosystem. Start with the official 18.3 warning step, then React/DOM/types together; exercise drag/drop, transitions, forms, portals, and virtualized lists. React 19.3 is only a week old at this audit date. [React 19](https://react.dev/blog/2024/12/05/react-19), [React 19.2](https://react.dev/blog/2025/10/01/react-19-2), [upgrade guide](https://react.dev/blog/2024/04/25/react-19-upgrade-guide).

**Database and packaging constraints**

`server/scripts/make-bin.ts` interpolates the exact better-sqlite3 dependency string into a GitHub release URL with a Node ABI suffix. It targets Linux x64/arm64, Alpine x64, macOS x64/arm64, and Windows x64. `server/scripts/bundle.ts` copies native bindings and emits a Node-22-targeted CommonJS bundle. Version 13 moved to N-API and ships prebuilds with npm code instead of the previous distribution mechanism. The existing downloader therefore needs redesign before adopting v13. The upside is reduced Node-ABI coupling, newer SQLite, and new query debugging helpers. Version 13.0.2 also fixed a process abort on worker-thread termination. [better-sqlite3 releases](https://github.com/WiseLibs/better-sqlite3/releases).

Keep better-sqlite3 exactly pinned while that script consumes the dependency string. Validate fresh databases, upgrades of representative existing databases, migrations, transactions, backups, and packaged startup across the supported targets. An intermediate 12.x upgrade is worth evaluating if v13 packaging work is too large; its prebuild availability still needs checking.

`patches/kysely.patch` edits ESM exports and exposes internal types. An update must determine which additions are now public and either remove or rebase the patch. `server/src/db/DBAccess.ts` runs Kysely and Drizzle together, while schema/helper code bridges their types. Upgrade these separately so type and SQL behavior changes remain attributable. Kysely 0.28 introduced manually controlled transactions, savepoints, resource disposal, and empty-IN-list handling. [Kysely 0.28 release](https://github.com/kysely-org/kysely/releases/tag/0.28.0).

Drizzle 0.45.2 fixes identifier and alias escaping; this is a concrete reason to advance the stable 0.x line, without adopting the 1.0 beta. Check schema typing, generated SQL, and migration output; a dependency bump should not introduce an unexplained schema migration. [Drizzle 0.45.2](https://github.com/drizzle-team/drizzle-orm/releases/tag/0.45.2).

Meilisearch has two versions to manage: SDK 0.50.0 and engine 1.30.0 in `server/package.json`. SDK 0.62 improves timeout-error credential redaction and adds index size statistics; newer SDK methods may require newer servers. Test current operations against the bundled engine before changing it. An engine migration needs its own index migration/rebuild and rollback assessment. This audit does not establish the latest engine version or an engine upgrade path. [SDK 0.62 release](https://github.com/meilisearch/meilisearch-js/releases/tag/v0.62.0).

**UI compatibility constraints**

MUI 9 improves keyboard/focus behavior and API consistency, and adds NumberField and Menubar. Its removed deprecated props matter here: Tunarr still uses `InputProps`, `inputProps`, and `PaperProps`. Apply appropriate codemods and inspect rendered behavior, theme overrides, dialogs, autocomplete, and date/time editing. Browser targets also advance, which matters for older clients. [MUI 9 migration](https://mui.com/material-ui/migration/upgrade-to-v9/), [MUI 9 announcement](https://mui.com/blog/introducing-mui-v9/).

`material-react-table` is already at its latest published version, 3.2.1. Its broad peers permit newer React/MUI versions, but that is not proof of working behavior. It depends on TanStack Table 8.20.6, while Tunarr directly pins 8.19.3 and imports pagination/sorting types. Do not independently jump the direct Table package to latest 9.2.4; align within v8 first and evaluate the wrapper before any v9 move. [MRT package metadata](https://registry.npmjs.org/material-react-table/3.2.1).

Zustand v5 requires stable selector outputs and changes persistence/equality behavior. Existing `useShallow` usage helps, but does not establish that every selector is safe. `web/src/store/index.ts` combines Immer, devtools, and persistence with a custom merge. Test stored settings/theme hydration and editor updates; a direct bump can produce rendering loops even when typechecking passes. Update to the latest v4 first, as upstream recommends. [Zustand migration](https://zustand.docs.pmnd.rs/reference/migrations/migrating-to-v5).

The lineup and media lists use react-window v1 APIs such as `FixedSizeList` and `ListChildComponentProps`. Treat v2 as component migration work, covering scroll restoration, selection, resize, drag/drop, and large lineups. The latest v2 peers accept React 18 and 19, so this work need not be coupled to the React major. [react-window documentation](https://github.com/bvaughn/react-window).

**Build and runtime constraints**

Vite 8 replaces the underlying bundler/transforms with Rolldown/Oxc. Tunarr's configuration explicitly sets esbuild options and combines SWC, Lingui, router generation, and SVGR. Check every plugin and compare production assets, source maps, SVGs, translations, and route generation. Vite's performance claims require a local benchmark before assigning a Tunarr speedup. Its v7.3 line still receives important/security fixes, providing a smaller first step. [Vite migration](https://vite.dev/guide/migration), [release policy](https://vite.dev/releases).

TypeScript 7 is stable, but has no compiler API in 7.0. Builds already use the native preview's `tsgo`; replacing `typescript` 5.9.3 alone would neither update those scripts nor necessarily preserve tools using the old compiler API. Follow the documented side-by-side approach if generators/API Extractor still need it, migrate commands intentionally, and compare declaration output. Also update the workspace-wide `@types/node` override from 22.10.7: it is below Vite 8's declared ^20.19.0 or >=22.12.0 peer range. [TypeScript 7 announcement and compatibility approach](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/).

Lingui v6 is ESM-only, requires Node >=22.19, and changes generated message IDs to a URL-safe form. Update core/react/CLI/format/SWC/Vite packages together, regenerate catalogs, and verify translations and macro transforms. The declared 22.20 runtime clears that floor. [Lingui migration](https://lingui.dev/releases/migration-6).

Node 22 remains LTS; Node 24.21.0 is the current LTS release shown by upstream, while 26 is Current. Patch the existing runtime first, then evaluate Node 24 with `@yao-pkg/pkg`, native bindings, and executable targets. `.nvmrc` and the executable builder pin 22.20.0; Docker installs the moving 22.x line, so they do not inherently use the same patch. [Node release status](https://nodejs.org/en/about/previous-releases).

Pino 9.14→10.3, pino-roll 1.3→4, sonic-boom 4.2→5, and thread-stream 3.1→4 should be evaluated as a logging/bundling group. The esbuild Pino plugin explicitly bundles transports. Validate rotation, worker loading, and shutdown in the executable. For these secondary packages, this audit identifies integration risk rather than claiming a complete release-by-release feature review.

**Security cross-check**

The GitHub API returned 262 open Dependabot alerts across all pages: 5 critical, 135 high, 107 medium, and 15 low. A fresh `pnpm audit --json` reported 276 vulnerability occurrences: 7 critical, 144 high, 105 moderate, and 20 low. These are different snapshots/counting models, include repeated dependency paths, and are not counts of independently exploitable application vulnerabilities. [Repository alerts](https://github.com/chrisbenincasa/tunarr/security/dependabot).

Prioritize runtime input boundaries: Axios, Fastify, XML parsing, and database query construction. Fast XML Parser is used by Plex and NFO parsing. Its 4.5.3 release has entity-expansion advisories; some fixes exist in 4.5.5, but another XMLBuilder advisory requires >=5.7.0, so “patch v4” must not be presented as clearing all findings. Evaluate latest v5.11.1 against parser options and XML fixtures. Kysely findings include JSON-path handling and a MySQL-specific issue; Tunarr's SQLite backend means those need individual reachability assessment. Drizzle's identifier fix lands in 0.45.2. [XML entity advisory](https://github.com/advisories/GHSA-8gc5-j5rx-235r), [XMLBuilder advisory](https://github.com/advisories/GHSA-gh4j-gqv2-49f6), [Kysely JSON path advisory](https://github.com/advisories/GHSA-pv5w-4p9q-p3v2), [Drizzle advisory](https://github.com/advisories/GHSA-gpj5-g38j-94v9).

Critical findings also occur through release tools, Drizzle Kit, and web devtools. For example, `basic-ftp` is reached through release-it's proxy stack and `seroval` through React devtools/Solid. They require remediation, but the package graph alone does not establish exposure in the shipped app. Likewise, esbuild's development-server issue is not evidence that Tunarr's server bundling call is exploitable. Refresh parent dependencies and transitive resolutions, then rerun the audit and inspect remaining paths rather than applying blanket major-version overrides.

**Suggested delivery order and acceptance checks**

1. **Small security and maintenance changes.** Axios 1.x, Fastify 5.x, Vite 7.3 patches, Vitest 4.x patches with matched coverage, tar/tmp, and affected transitives. Assess XML v5 and Drizzle 0.45.2 in their own changes. Require typechecks, relevant tests, API validation/streaming checks, and a fresh advisory diff. Avoid blind `audit --fix` overrides.
2. **Playback and data fetching.** HLS.js 1.7, then Query/devtools and Router tooling in separate changes. Validate playback scenarios, route generation/deep links/search parameters, generated hooks, mutations, pagination, and invalidation.
3. **Database and executable packaging.** Resolve the Kysely patch, upgrade each query layer independently, then redesign native binary handling for better-sqlite3 13. Require database fixtures and startup checks on all supported executable targets before release.
4. **Build/compiler modernization.** Stable native TypeScript with compiler-API compatibility, server esbuild/packager/logging updates, then Vite 8 and Lingui 6 with compatible plugins. Require declaration builds, application tests, production bundles, catalog consistency, and a measured build-time comparison.
5. **UI migrations.** React 18.3 warnings → React 19, Zustand v5, MUI v9/date pickers, and virtualization in individually reviewable changes. Prioritize editor persistence, large lineups, drag/drop, tables, forms, dialogs, and browser support.

Defer upgrades with little demonstrated payoff until their own use case or advisory justifies them. For example, cron-parser 4.9→5.10 needs special care: `server/src/util/schedulingUtil.ts` imports `cron-parser/lib/expression` internals, with a local declaration file. A migration must replace those internals and validate offsets/DST, not just resolve compile errors. Chevrotain 11→13 similarly deserves parser/grammar regression coverage. New major versions of uuid, yargs, file-type, and tooling should be small independent changes with engine/ESM checks.

Prevent renewed lag by using bounded Axios ranges instead of `>=1.12.0`, grouping coupled tools in update automation, and checking resolved lockfile versions regularly. Retain exact pins where packaging or generated code makes them intentional. pnpm itself is pinned at 10.28.0 versus registry latest 12.4.2; assess its workspace/catalog/build-policy migration separately from application packages. Native FFmpeg/container contents, macOS platform dependencies, and a full binary supply-chain scan are outside this JavaScript dependency audit.
