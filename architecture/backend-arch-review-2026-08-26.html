Problem. Every handler's real interface is one 30-field object reached through AsyncLocalStorage and req.serverCtx — plus container.get() calls inside handlers. A handler's dependencies are invisible, every handler couples to the whole world, and getServerContext() throws when ambient state is missing.

Solution. Routers declare dependencies at construction (constructor @inject, like the newer *ApiController classes) and receive a request context carrying only request data; the container resolves one router factory, never per-handler lookups.

  • locality: dependencies visible at each router
  • testability: handlers become fakes-injectable (today: 0 handler tests)
  • leverage: one convention replaces 250 ambient reads
  • kills the service locator half of Inversify

The factory collects inputs into clean setter fields, then flattens them into positional constructor arguments whose order differs per adapter — concat/watermark/subtitle for Nvidia/Qsv/VideoToolbox, watermark/subtitle/concat for Vaapi/Software. A latent argument-swap hazard that BasePipelineBuilder already half-solves with its PipelineBuilderContextProps object.

Solution. Pass the already-merged context object through every constructor; the factory builds it once instead of re-ordering positionals per hardware mode.

  • leverage: one context object
  • locality: add an input in one spot
  • no order-dependent swap bugs
